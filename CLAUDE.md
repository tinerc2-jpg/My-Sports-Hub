# My Sports Hub

Single-file web app (`index.html`): a landing page plus a React 18 fan dashboard (loaded from cdnjs, written with `React.createElement` as `h`, no build step).

## Structure
- Landing page markup + CSS at the top of `index.html`.
- `mountApp()` contains the dashboard: `DB` (hardcoded team/player data, added via `add([...keys], {...})`), `FS_IDS` (Flashscore links), `HINTS`, components (`App`, `FavBar`, `AddModal`, `NextGame`, `StandingDisplay`, …).
- Favourites persist in `localStorage` (`msh-teams`, `msh-sel`). `refreshFromDB` re-applies DB data on load.
- Live data: `fetchTeamLive(team)` auto-updates results / next game / standings from free CORS APIs — ESPN (football, NBA, NHL, NFL, MLB), Jolpica (F1), TheSportsDB (handball). `resolveSource` finds the team id by name (cached in `msh-src`), results are cached in `msh-live`, and `mergeLive` overlays them on the static DB entry. If a host blocks the browser (CORS), `getJSON` retries via public CORS proxies (`CORS_PROXIES`: corsproxy.io, allorigins) — approved by the owner. Sections still showing static data are labelled "saved May 2026". `App` ticks every 30s; `liveIsStale` decides refetches (1 min during live games / around kickoff, 10 min for the selected team, 30 min for others).
- GitHub snapshot (owner-approved): `.github/workflows/update-live-data.yml` runs `scripts/update-live.mjs` every 15 min. The script evals the live-data block of `index.html` (between `// ── Live data (auto-updating results)` and `// ── end live data fetchers` — keep those markers) plus the `add([...])` lines, fetches every DB team and force-pushes `live.json` to the `live-data` branch. When a direct fetch fails, the app falls back to that file (`SNAPSHOT_URL`, shown as "… via GitHub"). Custom teams that aren't in DB aren't in the snapshot.
- PWA: `manifest.webmanifest` + install banner (iOS Safari / `beforeinstallprompt`). Icon: "SH" monogram (white S, pink H, pink underline on a purple gradient) as real files next to `index.html` — `icon.svg`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` (iOS ignored the earlier data-URL icons). Netlify is deployed by **Netlify Drop**, so upload a zip of `index.html` + these files, not `index.html` alone.
- Colours follow the owner's Netlify version: purple page `#4b3d5a`, near-black nav `#1c1b1f`, pink accent `#e8409a` (`:root` vars at the top). The dashboard (`#app-view`, inline styles in `mountApp`) uses the same palette: page `#4b3d5a`, header `#1c1b1f`, modals `#2e2440`, accent `#e8409a` (white text on accent buttons).

## Known issues / TODO
- Tennis (`fetchTennis`: ESPN `tennis/{atp|wta}/scoreboard` singles matches + `/rankings`) and golf (`fetchGolf`: ESPN `golf/{pga|eur|lpga}/scoreboard` per `GOLF_TOURS`, position computed from to-par when not given; men's OWGR rank added server-side via `owgrStanding`, with a same-last-name spelling fallback; rolexrankings.com returns 403 to Actions, so women have no rank. ESPN's ATP calendar is date-only, so tennis shows no 'next tournament') are live. ESPN only shows the current week, so `scripts/update-live.mjs` merges earlier tennis/golf results from the previous snapshot (rows carry `ts`). Response shapes are untested against the real API — check the Actions log (`tennis …`, `golf …`, `OWGR …`).
- Cycling, rugby, volleyball have no live results source yet (static May–June 2026 data). News: `scripts/update-live.mjs` fetches RSS per DB team — 🇩🇰 teams: DR Sporten RSS + Bing News da-DK, kept only when the headline names the team (`mentions`, ø→o folding), then Google News en-GB with the English sport word if fewer than 3 (Google has no Danish edition; Bing da-DK returns little from Actions). `NEWS_V` invalidates reused news when the logic changes, at most hourly per team (reuses `newsTs`), 5 items `{title,url,ts,src}`. Teams without a results source get `{newsOnly:true}` snapshot entries; the app merges snapshot news when its own fetch has none. Handball standings: TheSportsDB `lookuptable.php` first (returned no rows for Håndboldligaen on the free key), then `wikiStanding` parses the `{{#invoke:Sports table}}` wikitext of the en.wikipedia "<season> <league>" article (rank = position in `team_order`, points from `win_points`/`draw_points`/`adjust_points_X`). `liveLog()` lines are printed per team in the Actions log. In the Actions log TheSportsDB's table came back empty and no 2026–27 Wikipedia article exists (league renamed "Bambuni Herreligaen"), so the real source is **API-Sports handball**, server-side only: `scripts/update-live.mjs` uses the `APISPORTS_KEY` repo secret (never put the key in `index.html`). It refreshes at most hourly, reusing the previous `live.json` (`standingFrom`/`standingTs`/`standingTriedTs`), to stay under the 100 requests/day free quota. The app merges the snapshot's standing when its direct fetch has none. API-Sports' free plan only covers seasons 2022–2024, so for Håndboldligaen teams the script then reads public table pages (`TABLE_PAGES`: tophaandbold.dk → TV 2 → gog.dk), first from embedded JSON, then from the page text. A row is used only if W+D+L = played and points = 2W+D. When a live source gives no table, the standing is blanked ("not available yet") instead of showing May data.
- Live API response formats were written from docs, not verified against the real endpoints yet. In the owner's browser ESPN was blocked and both CORS proxies failed (TheSportsDB worked) — hence the GitHub snapshot.
- `triggerInstall()` reads `window._deferredPrompt`, but the listener stores the event in a local `deferredPrompt` — the Install button does nothing.
- GOG's recent results / news disagree with the landing-page mockup (Aalborg vs Skanderborg AGF).
- `FS_IDS` key "FC Bayern Munchen" doesn't match DB name "FC Bayern München".

## Run
Open `index.html` in a browser, or `python3 -m http.server` in this folder.
