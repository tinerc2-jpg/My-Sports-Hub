# My Sports Hub

Single-file web app (`index.html`): a landing page plus a React 18 fan dashboard (loaded from cdnjs, written with `React.createElement` as `h`, no build step).

## Structure
- Landing page markup + CSS at the top of `index.html`.
- `mountApp()` contains the dashboard: `DB` (hardcoded team/player data, added via `add([...keys], {...})`), `FS_IDS` (Flashscore links), `HINTS`, components (`App`, `FavBar`, `AddModal`, `NextGame`, `StandingDisplay`, …).
- Favourites persist in `localStorage` (`msh-teams`, `msh-sel`). `refreshFromDB` re-applies DB data on load.
- Live data: `fetchTeamLive(team)` auto-updates results / next game / standings from free CORS APIs — ESPN (football, NBA, NHL, NFL, MLB), Jolpica (F1), TheSportsDB (handball). `resolveSource` finds the team id by name (cached in `msh-src`), results are cached in `msh-live`, and `mergeLive` overlays them on the static DB entry. If a host blocks the browser (CORS), `getJSON` retries via public CORS proxies (`CORS_PROXIES`: corsproxy.io, allorigins) — approved by the owner. Sections still showing static data are labelled "saved May 2026". `App` ticks every 30s; `liveIsStale` decides refetches (1 min during live games / around kickoff, 10 min for the selected team, 30 min for others).
- GitHub snapshot (owner-approved): `.github/workflows/update-live-data.yml` runs `scripts/update-live.mjs` every 15 min. The script evals the live-data block of `index.html` (between `// ── Live data (auto-updating results)` and `// ── end live data fetchers` — keep those markers) plus the `add([...])` lines, fetches every DB team and force-pushes `live.json` to the `live-data` branch. When a direct fetch fails, the app falls back to that file (`SNAPSHOT_URL`, shown as "… via GitHub"). Custom teams that aren't in DB aren't in the snapshot.
- Netlify: really linked to GitHub `main` on 14 Oct 2026 at 17:02 (before that it said "Last deployed from Netlify Drop" and PRs #32–#47 were not live until a zip upload) — merging to `main` deploys mysportspage.netlify.app automatically; `netlify.toml` = publish `.`, no build. Check: Netlify posts a commit status / check on GitHub for each deploy.
- Football European cups: `fetchEspn` also reads the club's `uefa.champions` / `uefa.europa` / `uefa.europa.conf` schedules with the same ESPN id (`ESPN_EURO_CUPS`); those games are tagged "· CL" / "· EL" / "· ECL" in results and next game. A cup answer that is mostly the league's own games is skipped (logged `espn cups …` in Actions).
- Mobile UI (14 Oct 2026): `FavBar` is one swipeable row with "+ Add" pinned right; team card wraps (buttons under the name); `StatBox` is `flex:1 1 120px` (2×2 on phones). `AddModal`: ✕ close and "← Back" on every step, the phone's back button/Escape step back (`history.pushState`), tapping a sport goes straight to search, input 16px (no iOS zoom). Spelling help: `suggest()` (folded names, prefix/word/contains, then `editDist` typo match, chosen sport first) shows "Did you mean…" while typing and on the preview for unknown names.
- Match stats (15 Oct 2026): ESPN result rows carry `ev`/`lg`/`sp`/`tid`; tapping one opens `MatchSheet` (goals, team stats bars, period scores). Data: `fetchEspnSummary` (ESPN `summary?event=`), prefetched by the robot into `row.stats` for the last 5 results (reused from the previous snapshot by `ev`, since finished games don't change); the app uses `row.stats`, else fetches live, else the snapshot. Football and handball matter most to the owner.
- Full table: `standing.table` = rows `{r,n,p,w,d,l,gd,pts,pct,me}` — ESPN (`espnTable`, the team's group), F1 (all drivers), tennis (top 10 + rows around the player), handball (robot's `hbTableFromTokens` over the table page text, same W+D+L / 2W+D checks, used only with ≥8 rows incl. our team). The Position/Rank box shows "See table ›" and opens `TableSheet`. `Sheet` is the shared bottom sheet (✕, Escape, phone back).
- Usage stats: GoatCounter (owner's account, https://mysportshub.goatcounter.com, cookieless) – script tag in `<head>` counts page views; `showApp()` also sends an `/app` "Opened dashboard" event once per load. Localhost visits aren't counted.
- PWA: `manifest.webmanifest` (`start_url: ./?app`) + install banner (the Install button uses `window._deferredPrompt`). Opened from the home-screen icon (standalone display mode, `?app` or `#app`), the page skips the landing page and calls `showApp()` directly (script after `mountApp`); in standalone the landing `#app-topbar` is hidden. Install banner: iOS Safari / `beforeinstallprompt`. Icon: "SH" monogram (white S, pink H, pink underline on a navy gradient) as real files next to `index.html` — `icon.svg`, `icon-192.png`, `icon-512.png`, `apple-touch-icon.png` (iOS ignored the earlier data-URL icons).
- Colours (owner's choice, 14 Oct 2026): **navy + pink** everywhere. Landing `:root`: `--bg:#0f1b33`, nav `rgba(10,19,38,.94)`, accent `#e8409a`. Dashboard (inline styles in `mountApp`): page `#0f1b33`, header `#0a1326`, modals `#16264a`, accent `#e8409a` for backgrounds/borders only (white text on accent buttons); pink *text* uses the lighter `#ff9fd0` for readability on navy, higher-contrast text (labels at opacity .7–.8, secondary text `#d5deee`). Icon background is a navy gradient (`#1d3360`→`#0a1326`).
